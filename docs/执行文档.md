# DigiPlayers 执行文档

一次只做一步。该步的验收通过后，再开始下一步。不要在同一步里夹带后面的内容。

本轮的完成标准：一个新用户从创建身份走到四个练习全部结束，每一步都知道下一件是什么。界面上积分只表示「这一节做完了」。

路径顺序固定为：

1. 章节 `ch_001`：阅读并测验通过
2. 区块链拼图（`game_done_game_block`）
3. 哈希碰碰乐（`game_done_game_hash`）
4. P2P 节点模拟器（`game_done_game_p2p`）
5. 章节 `ch_002`：阅读并测验通过
6. 反诈识别训练营（`game_done_game_antiscam`）

「继续」永远指向这六步里第一个还没完成的。章节完成记在 Hive `learn_progress` 的 `completed_ch_001` / `completed_ch_002`。游戏完成沿用现有的 `game_done_*` 键，不要另起一套标记。

## 步骤 1 · 用助记词恢复身份

状态：已完成。页面在 `lib/features/auth/recover_screen.dart`。

现状：`DIDGenerator.recover` 已经能从 12 个词算出同一把密钥。路由 `/recover` 的 `RecoverScreen` 仍是占位页「Recover 流程待实现」。入口在 `lib/features/auth/register_screen.dart`。

- 复用 `lib/core/did/did_generator.dart` 的 `recover`
- 写入方式对齐 `lib/features/auth/register_screen.dart`：`SecureStorage.saveIdentity`、`saveMnemonic`，然后 `DIDAuth.authenticate()`

行为：

- 一个输入框，接受 12 个词，空格分隔。提交前先 `bip39` 校验，不合法就停在本页。

## 进度挂到 DID

一次只做一步。该步验收通过后，再开始下一步。这一轮要改两个仓库：Flutter 在本仓库，接口在旁边的 `digiplayers-workers`。

本轮的完成标准：同一组助记词在另一台设备上恢复之后，六步完成、已读卡片、由此算出的徽章，和原设备一致。积分和昵称本来就在服务端，保持原样。

服务端这份进度是账号本身。本机 Hive 只缓存「这个 DID 上次从服务端拉成功的那一份」，用来断网时继续显示。换一台设备看到的是同一份；同一台手机换另一组词，看到的是那一组词对应的 DID，不会带上一个身份的进度。

### 本轮不做

- 不把更新前已经写在 Hive 里的完成标记上传。上线后第一次拉成功，本机这六步和已读卡片改成服务端的结果；服务端没有的，就当成没做完。
- 不从 `points_ledger` 反推哪一章、哪一个练习做完了。积分上报仍然失败也不挡住学习，但它不是进度。
- 不做离线完成队列。服务器没记下之前，本机不算完成。
- 不改主题、不改「三句话已看过」。语言和昵称已经在 `users` 表里。
- 不做会话互踢、设备数量上限、邮箱或手机二次验证，也不做被盗后换一把新 DID。

允许写入的六个标记，名字就用现在的：

- `completed_ch_001`
- `completed_ch_002`
- `game_done_game_block`
- `game_done_game_hash`
- `game_done_game_p2p`
- `game_done_game_antiscam`

已读卡片另记，不塞进这六个标记。

## 步骤 1 · 服务端按 DID 记下进度

状态：已完成。接口代码和 `schema.sql` 已写入。远程库这次没有执行成功，当前环境的 wrangler 没有 Cloudflare 登录态。在 `digiplayers-workers` 目录执行下面两条之后，真机上的进度才会记到 DID 上：

```
wrangler d1 execute digiplayers-db --remote --file=schema.sql
wrangler deploy
```

现状：D1 只有用户、积分和行为目录（`digiplayers-workers/schema.sql`）。没有进度表。`src/index.js` 没有进度路由。完成标记只存在客户端 Hive。

改这些文件：

- `digiplayers-workers/schema.sql` 末尾追加建表，并对已有的 `digiplayers-db` 执行同一段 SQL（`wrangler d1 execute`）。不要改 `wrangler.toml` 里的 Durable Object migration，那个和这张表无关。
- 新增 `digiplayers-workers/src/progress/progress.js`
- `digiplayers-workers/src/index.js` 挂上路由

表：

```sql
CREATE TABLE IF NOT EXISTS user_progress (
  did TEXT NOT NULL,
  flag TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (did, flag)
);

CREATE TABLE IF NOT EXISTS user_read_cards (
  did TEXT NOT NULL,
  card_id TEXT NOT NULL,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (did, card_id)
);
```

鉴权与 `src/user/profile.js` 相同：`Authorization: Bearer` 用 `verifyJWT`，没有或过期返回 401。

`GET /user/progress` 永远返回全部六个标记和已读列表，没有行的标记是 `false`：

```json
{
  "flags": {
    "completed_ch_001": false,
    "completed_ch_002": false,
    "game_done_game_block": false,
    "game_done_game_hash": false,
    "game_done_game_p2p": false,
    "game_done_game_antiscam": false
  },
  "read_cards": []
}
```

`POST /user/progress` 一次只收一件，两样互斥：

- `{ "flag": "completed_ch_001" }`：不在白名单里返回 400。已存在则原样成功，不改 `updated_at`。
- `{ "card_id": "..." }`：非空字符串，最长 64。已存在则原样成功。

不提供删除。标记只能从无到有。

验收：

- 新 DID 第一次 GET，六个都是 `false`，`read_cards` 为空。
- 对同一个 DID 把六个标记和一张卡片各 POST 一次，再 GET，与写入一致。同一条再 POST 一次，仍然只有一行。
- 不带 JWT、flag 不在白名单、flag 和 card_id 同时出现，都不写表。
- 另一个 DID 的 GET 看不到这些行。
